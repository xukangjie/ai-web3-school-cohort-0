## 📚 今日学习内容

### Framework = Agent 的 SOP

用国网工作类比理解：

| | 我的工作 | Agent |
|------|------|------|
| 流程叫 | SOP（标准操作流程） | Framework |
| 谁定的 | 公司制度 | 开发者写的代码 |
| 能改吗 | 不能，只管执行 | 用户不能改，只管用 |
| 内容 | 收到付款申请 → 核对金额 → 检查审批 → 付款 → 归档 | 收到消息 → 拼Context → 问LLM → 调工具 → 循环 → 输出 |

### Framework 就是人脑的思维逻辑

> 看到一个事情 → 脑袋里综合分析 → 思考复盘 → 做出决定 → 执行

这整个过程，在 Agent 里就叫 Framework。

### 最小实践：两种实现方式对比

同一个任务（从合同里提取关键信息填表）：

| 对比维度 | 方式一：直接调 API | 方式二：框架式 |
|------|------|------|
| 代码量 | 14 行 | 140 行 |
| 像什么 | 便利贴（口头交代） | SOP 手册（书面流程） |
| 加新功能 | 改一处影响全局 | 插一个新模块就行 |
| 出问题时 | 黑箱，只能猜 | TRACE 日志能追溯每一步 |
| 适合场景 | 一次性小任务 | 长期维护的产品 |

**核心理解：框架不是让事情变简单，而是让事情变得「可维护」。**

## 💡 思考与收获

### Framework 核心理解

- Framework 定义了 Agent 做事的那套死规矩——先做什么、后做什么、什么时候循环、什么时候结束
- LLM 是大脑，Framework 是 SOP，Agent 是靠 SOP 驱动大脑和手脚协调工作的系统
- Handbook 里的代码块就是开发者用编程语言写的 SOP，跟公司用文字写 SOP 没本质区别

### 框架选择的原则

| 判断标准 | 含义 |
|------|------|
| 框架要能退出 | 如果换模型、换工具很困难，长期成本高 |
| 先画流程再选框架 | 很多失败项目是先引入框架再迁就框架 |
| 简单任务不需要框架 | 短流程保持简单，长流程才需要显式状态 |
