## 📚 今日学习内容

### Smart Contract（智能合约）

**核心纠正：** 智能合约不是"自动执行的法律合同"，是**部署在链上的程序**。

**关键概念：**
- **Solidity** — 写合约的语言，重点是链上特有的 storage、msg.sender、event
- **ABI** — 合约的"菜单"，告诉你能调什么、参数是什么、返回什么。但 ABI 是机器可读接口，**不是安全说明书**——它不告诉你调用是否危险
- **Event** — 合约的"广播喇叭"，让外部系统能追踪发生了什么（如 Transfer、Approval）
- **只读 vs 写** — 查余额免费不需要签名；改状态需要签名+付 Gas
- **权限函数** — mint/pause/burn/blacklist 这些"上帝按钮"在谁手里，决定了合约的风险边界

**最小实践（USDC 合约）：**
- 合约地址：0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48
- 只读函数：name, symbol, decimals, totalSupply, balanceOf, allowance
- 写函数：transfer, approve, transferFrom
- 权限函数：mint（masterMinter）, burn, pause（pauser）, blacklist（blacklister）
- 风险边界：Circle 公司掌握上帝模式——能印钱、烧钱、冻结、关停
- **核心洞察：代码公开 ≠ 去中心化，要看清谁握着特权**

### Account Abstraction（账户抽象）

**问题：** EOA 钱包的限制——一把钥匙管一切、必须付 ETH 做 Gas、每步都签名、权限太粗

**解决方案：** 把账户变成智能合约，让账户可以编程

**ERC-4337 四个角色：**

| 角色 | 作用 |
|------|------|
| UserOperation | 用户的操作请求 |
| Bundler | 收集操作、打包提交 |
| EntryPoint | 统一入口，验证+执行 |
| Paymaster | 替用户付 Gas |

**Session Key — 对 AI × Web3 最重要：**
- 给 Agent 的临时权限，不拿主私钥
- 可限制：额度、合约、方法、时间、次数
- 超出限制必须回到用户确认
- 可随时撤销

**最小实践（Session Key 策略设计）：**
- 场景：Agent 每天自动查余额，跌超 5% 就提醒
- 允许操作：balanceOf()（只读）
- 最大金额：0（只读场景）
- 过期时间：1 天
- 必须确认：超出额度、改策略、转出资产
- 撤销：钱包里一键取消
- 审计：回看操作日志
