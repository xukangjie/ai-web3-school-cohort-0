## 📚 今日学习内容

### 核心理解

> **什么是 Prompt？**
> Prompt 是告诉大模型我的需求，让他按照我的要求来输出。

> **Prompt 的要素（我自己总结的）：**
> 1. **任务目标** — 我要做什么
> 2. **可用信息** — 模型可以依赖什么材料
> 3. **输出格式** — 结果应该长什么样
> 4. **安全限制** — 不能做什么
> 5. **边界设置** — 范围/场景限定

> **Prompt 的本质：** 它是我和模型之间的桥梁。

### 关于 Prompt Injection 的思考
> 普通个人用户应该不需要太担心 Prompt Injection，这个是需要真实落地大规模应用的需求才要认真重视的。普通用户只需要基本的防范意识——**不要明文写入 API Key、密码等敏感信息**。

## 💡 思考与收获

### 将自己的总结与 LLM 理解联系起来

之前我对 LLM 的理解是：LLM = 超级工匠，从我给的材料里做概率最高的输出。

现在加上 Prompt 的理解：**Prompt = 给这个工匠的施工图纸**。

图纸画得越清楚（任务目标、格式、边界），工匠就做得越接近我想要的。

### 一个被验证的认知风格

> 我发现自己很难一次性把需求描述清楚，会默认省略很多信息。需要别人追问才能理清真正想要什么。
>
> 所以写 Prompt 最好的方式不是追求"一次性完美"，而是**多轮对话**——先写一版粗糙的，模型给出了，不满意再改。

这个认知本身就是学习 Prompt 工程最大的收获 👍

## 💡 Context 的理解（2026-05-23 下午补学）

### 核心认知
> **Prompt 是我能决定的（给你发指令），Context 是你的能力（你组装给模型的信息包）。**
> 
> 我对 Context 只有影响力（通过 Prompt 和长期使用积累的记忆），没有控制权。
> 控制权在设计者手里——他们决定了系统规则、Skill、工具调用逻辑。

### Context 设计思维
设计一个 Agent 的 Context，需要三步：
1. 想用户会对助手说什么（列举3个以上例子）
2. 想助手回答前需要知道什么信息
3. 分类放进 Context 的各层（指令层/任务层/知识层/事实层/记忆层）

**关键认知：** Context 设计不是一次写好的蓝图，而是反复迭代的结果。
先做一版 → 在实践中发现问题 → 再改 → 再迭代。

### Context vs Prompt vs 输出
| 概念 | 谁决定的 | 内容 |
|:----|:--------|:----|
| Prompt | 用户发的指令 | 几十个字 |
| Context | Agent 组装的完整信息包 | 系统规则+Prompt+历史+记忆+工具结果 |
| 输出 | 模型基于 Context 生成的回答 | 几百到几千字 |
