**主题：** AI × Web3 Bridge — Chain-aware Context

## 🧠 核心概念

### Chain-aware Context vs 普通 Context

| | 普通 Context | Chain-aware Context |
|---|---|---|
| 信息来源 | 用户给的 + 工具查的 | **链上实时数据** + 用户给的 + 工具查的 |
| 变化触发 | 用户互动 | **区块在跑**（用户不动，数据也在变） |
| 可信度 | 靠设计者把关 | 靠**链上证据 + Citation** 把关 |
| 是否区分事实/解释 | 通常不区分 | **必须区分**：链上事实 ≠ 模型解释 |

### 三个关键新增要求

1. **实时性** — 链上状态随区块变化，不能缓存
2. **Citation（引用）** — 每条信息必须带交易哈希、区块号、explorer 链接，可被验证
3. **事实 vs 解释分离** — 模型不能把猜测伪装成链上数据

## 🔬 最小实践

用一笔真实 USDC 交易组装了 Chain-aware Context 包：

- **交易：** 0x17195837678866ac1cb1635a1b548c109562a2c52145025dbe7c894957b9dd88
- **链：** Ethereum Mainnet (chainId=1)
- **区块：** 25235968
- **操作：** transferFrom — 从 0x4c2c... 转 23 USDC 到 0x7f53...
- **Explorer：** https://etherscan.io/tx/0x17195837678866ac1cb1635a1b548c109562a2c52145025dbe7c894957b9dd88

### 产出物

✅ 组装了结构化上下文包（chain id、block、from/to、amount、event、explorer 链接）
✅ 标注了每条信息是「链上事实」还是「解释」
✅ 每个结论附 citation

### 餐厅比喻延伸

- 普通 Context = 服务员记下你新点的菜 → 菜单更新了
- Chain-aware Context = 服务员发现厨房的食材**自己会减少**，每次不看就不知道还剩什么。而且告诉你鸡蛋在"3 号冰箱第 2 层有 12 个"，附上库存照片，你随时可以去核实。

---

## 💡 自己的理解

> Chain-aware Context 是一套给模型看的实时链上档案——不只看用户说了什么，还要实时查链上状态，每条信息带来源证据，事实和解释严格分开。普通 Context 是"用户告诉我的 + 我查的资料"，Chain-aware Context 在这个基础上多了一层"链上正在发生什么"。
