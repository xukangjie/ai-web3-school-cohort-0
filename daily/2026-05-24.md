## 📚 今日学习内容

### Agent = 服务员 🧑‍🍳（餐厅比喻完整版）

| 角色 | 对应什么 |
|------|---------|
| 🧠 厨师 | LLM（会做菜，不知道谁在吃） |
| 📝 点菜单 | Prompt（顾客的要求） |
| 📋 厨师看到的信息板 | Context（菜单 + 忌口 + 库存 + 桌号） |
| 🏃 服务员去后厨看库存 | RAG（先查资料再回答） |
| 🧑‍🍳 服务员 | Agent（接单、跑腿、协调、端菜） |

### Agent 四大核心能力

| 能力 | 含义 | 园丁比喻 |
|------|------|---------|
| 🔧 Tool Use | 调用外部工具（读文件、搜网页、写文件、调 API） | 锄头、肥料、水管 |
| 🗺 Planning | 把目标拆成可执行步骤 | 先松土 → 挖坑 → 放种子 → 浇水 |
| 📊 State | Agent 自己的记事本（记录进度、状态、结果） | 园丁口袋里的本子：第3株施过肥 |
| 🔍 Reflection | 做完后自查："做对了吗？还需要调整吗？" | 蹲下来看花："活了没？有虫吗？" |

### Handbook 最核心的一句话

> **模型负责提出候选行动，系统负责限制行动空间，用户负责批准高风险边界。**

### Agent 安全的核心原则

> 最危险的设计是让 Agent 同时拥有：模糊目标、广泛工具、长期记忆、大额资产权限。

- 🟢 读数据 — 低风险，可以自动执行
- 🟡 写文件 — 中风险，需要确认范围
- 🔴 发请求/付款 — 高风险，必须用户手动确认

**权限设计是 Agent 安全的第一道防线，不是 Reflection。**

### Multi-Agent

多个 Agent 各有专长，分工协作（研究 Agent + 写作 Agent + 安全审查 Agent）。

**核心警告：** 如果流程本身就不清楚，拆成多个不清楚的 Agent 只会更难调试。

## 💡 思考与收获

### 最重要的认知修正

**RAG 的执行者是 Agent（服务员），不是 LLM（厨师）。**

厨师只会做菜，不会自己去开仓库门。RAG 是 Agent 的能力——先去查资料，查到之后放进 Context，再给模型看。

### 完整的故事链

> 顾客（我）走进餐厅 → 服务员（Agent）迎接 → 顾客说要求（Prompt）→ 服务员记下偏好 → 服务员去后厨看库存（RAG）→ 服务员把所有信息写在本上（State）→ 把单子递给厨师（Context）→ 厨师做菜（LLM）→ 服务员端菜（Tool Use）→ 服务员尝一口（Reflection）

### LLM vs Agent 的准确理解

- LLM = 大脑（模型文件 + 推理程序）
- Agent = LLM + 工具 + 记忆 + 规划 = 完整的人
