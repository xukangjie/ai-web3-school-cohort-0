## 📚 今日学习内容

### 区块结构：一个关键纠正

❌ 错误理解：区块链 = 交易1 → 交易2 → 交易3 连成一条链
✅ 正确理解：多笔交易打包进一个区块，区块之间用哈希链接

```
┌──────────────┐      ┌──────────────┐
│   区块 #100   │      │   区块 #101   │
│  上一块hash:  │─────→│  上一块hash:  │
│   abc123     │      │   def456     │
│  含500笔交易   │      │  含500笔交易   │
└──────────────┘      └──────────────┘
```

### 共识机制：谁来打包下一个区块？

| | PoW（工作量证明） | PoS（权益证明） |
|------|------|------|
| 规则 | 谁先解出数学题谁打包 | 谁押的币多、押的久谁打包 |
| 消耗 | 费电 | 省电 |
| 惩罚 | 无（白费电） | 乱搞扣押金 |
| 代表 | 比特币 | 以太坊（现） |
| 共同点 | 目标都是选出打包者 | ← 同一个目标 |

共识流程：广播交易 → 共识选出打包者 → 打包进区块 → 所有节点独立验证 → 记入自己的账本

### 数字签名：核心技术

**流程：**

```
签名：  消息 → 算哈希 → 私钥加密哈希 → 得到签名
验证：  原文算哈希(A) ← → 公钥解密签名得哈希(B)
        A == B → 消息完整 + 签名真实 ✅
        A != B → 被篡改 ❌
```

**关键性质：**
- 私钥 → 公钥：算得出（单向）
- 公钥 → 私钥：算不出（反向破解几乎不可能）
- 验签：秒级（反向验证很容易）

### 动手实践：OpenSSL 签名全流程

在终端亲手跑了一遍（不依赖 AI 代理执行）：

1. `openssl genpkey` — 生成私钥（随机长数字）
2. `openssl pkey -pubout` — 从私钥推导公钥
3. `echo "Neo 向 小红 转账 1 ETH"` — 写消息
4. `openssl pkeyutl -sign` — 用私钥签名
5. `openssl pkeyutl -verify` — 用公钥验证 → ✅ Success
6. 改一个字（1 ETH → 100 ETH）再验证 → ❌ Failure

**结论：改一个字，签名立刻对不上。**

## 💡 思考与收获

### 存证的价值

之前学的存证 = 保证数据导出导入不被篡改，今天知道了技术实现：

```
内网导出数据 → 算哈希 → 私钥签名 → 哈希+签名上链
外网收到数据 → 重算哈希 → 公钥验签 → 对比链上记录
一致 → 数据完整 ✅    不一致 → 被篡改 ❌
```

### 知识串联

之前零散知道的概念，今天串成了线：

- 哈希 → 区块链的粘合剂（区块链接）+ 签名的基础（先算哈希再签）
- 公钥私钥 → 不只是一对数字，是签名和验签的工具
- 共识 → 解决了去中心化下「听谁的」这个核心问题

### 一句话总结

**区块链上每一笔交易 = 用私钥签名 + 广播到网络 + 共识选出打包者 + 所有节点独立验证。我今天在终端里跑的就是这个过程的第一步。**
